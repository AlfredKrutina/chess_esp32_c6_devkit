sequenceDiagram
    participant WDT as Watchdog
    participant LT as ledTask_P7_33ms
    participant MT as matrixTask_P6_25msMux
    participant BT as buttonTask_P5_5ms
    participant GT as gameTask_P4_100ms
    participant UT as uartTask_P3_1ms
    participant WT as webServerTask_P3
    participant GQ as gameCommandQueue
    participant BQ as buttonEventQueue
    participant URQ as uartResponseQueue
    participant LM as ledUnifiedMutex
    participant MM as matrixMutex
    participant UM as uartMutex
    participant GM as gameMutex
    participant HW as WS2812B_Hardware
    participant GPIO as GPIO_Hardware

    Note over WDT,GPIO: Main program flow after init - all tasks run in parallel<br/>MUTEXES: Protect shared resources (UART, LED state, Matrix state, Game state)<br/>QUEUES: Asynchronous inter-task communication<br/>DIRECT CALL: Fast synchronous communication with mutex protection<br/>NOTES: Thread-safe functions take mutex INSIDE (led_set_pixel_safe, game_get_status_json, game_get_board_json, game_send_response_to_uart)<br/>game_process_* functions run in game_task and do NOT take game_mutex (game_task has exclusive access to board[][])

    rect rgb(240, 240, 255)
        Note over LT,HW: LED TASK (Priority 7, 33ms cycle - 30 FPS)<br/>MUTEX: led_unified_mutex - Protect LED state (led_states[], led_pending_changes[])<br/>BATCH SYSTEM: Changes collected and committed atomically
        
        loop Every 33ms (led_task main loop)
            LT->>WDT: esp_task_wdt_reset_safe()
            LT->>LT: led_process_commands()
            LT->>LT: led_update_animation()
            LT->>LT: led_update_endgame_wave()
            LT->>LT: led_process_button_blink_timers()
            LT->>LM: xSemaphoreTake(led_unified_mutex)
            activate LM
            Note over LT,LM: Batch commit - atomic processing of all changes
            LT->>LT: led_privileged_batch_commit()
            Note over LT: Batch update system - commit all pending changes
            LT->>HW: led_strip_refresh() - ONE refresh of all LEDs
            Note over HW: WS2812B protocol - 800kHz, timing-critical
            LT->>LM: xSemaphoreGive(led_unified_mutex)
            deactivate LM
            LT->>LT: vTaskDelayUntil(33ms)
        end
    end

    rect rgb(255, 240, 240)
        Note over MT,GPIO: MATRIX TASK (Priority 6)<br/>Timer callback ~25ms: 20ms matrix + 5ms button window; task loop often 10ms<br/>MUTEX: matrix_mutex
        
        loop matrix_task loop (typically 10ms)
            MT->>WDT: esp_task_wdt_reset_safe()
            MT->>MT: matrix_process_commands()
            MT->>MT: vTaskDelayUntil(10ms)
        end
        
        Note over MT: Full row/column scan in timer callback (multiplex)
        MT->>MM: xSemaphoreTake(matrix_mutex)
        activate MM
        Note over MT,MM: Protect GPIO operations - prevent scan conflicts
        MT->>GPIO: matrix_scan_all() - Scan 8x8 Reed Switch matrix
        loop For each row (0-7)
            MT->>GPIO: Activate row (GPIO set LOW)
            MT->>GPIO: Read 8 columns (GPIO get level)
            MT->>MT: matrix_state[row*8+col] = (pin_level == 0) ? 1 : 0
            MT->>GPIO: Deactivate row
        end
        MT->>MT: matrix_detect_moves() - Detect changes (piece_lifted, piece_placed)
        MT->>GQ: xQueueSend(GAME_CMD_PICKUP) - Piece lifted
        MT->>GQ: xQueueSend(GAME_CMD_DROP) - Piece placed
        Note over MT,GQ: Async communication - game_task processes in its cycle (100ms)
        MT->>MM: xSemaphoreGive(matrix_mutex)
        deactivate MM
    end

    rect rgb(240, 255, 240)
        Note over BT,GPIO: BUTTON TASK (Priority 5, 5ms cycle)<br/>COMMUNICATION: button_event_queue - Async button event processing
        
        loop Every 5ms (button_task main loop)
            BT->>WDT: esp_task_wdt_reset_safe()
            BT->>GPIO: button_scan_all() - GPIO scan of all buttons
            BT->>BT: button_process_events() - State change detection
            alt Button pressed
                BT->>BQ: xQueueSend(BUTTON_EVENT_PRESS)
                activate BQ
                Note over BT,BQ: Async communication - game_task processes in its cycle
            end
            alt Button released
                BT->>BQ: xQueueSend(BUTTON_EVENT_RELEASE)
                alt Long press detected
                    BT->>BQ: xQueueSend(BUTTON_EVENT_LONG_PRESS)
                end
            end
            BT->>BT: vTaskDelay(5ms)
        end
    end

    rect rgb(255, 255, 240)
        Note over GT,GQ: GAME TASK (Priority 4, 100ms cycle)<br/>MUTEX: game_mutex - Protect game state (only in functions called from other tasks)<br/>QUEUES: game_command_queue, button_event_queue, uart_response_queue<br/>NOTE: game_process_* functions run in game_task - do NOT take game_mutex (game_task has exclusive access to board[][])
        
        loop Every 100ms (game_task main loop)
            GT->>WDT: esp_task_wdt_reset_safe()
            
            GT->>GQ: xQueueReceive(game_command_queue, 0)
            activate GQ
            alt Command in queue (max 15/cycle)
                GT->>GT: game_process_commands()
                alt GAME_CMD_PICKUP
                    GT->>GT: game_process_pickup() - Save position
                    Note over GT: Function runs in game_task - does NOT take game_mutex
                else GAME_CMD_DROP
                    GT->>GT: game_process_drop() - Detect move
                    GT->>GT: game_process_chess_move()
                    Note over GT: Function runs in game_task - does NOT take game_mutex
                else GAME_CMD_MAKE_MOVE
                    GT->>GT: game_process_chess_move() - UART/Web move
                    Note over GT: Function runs in game_task - does NOT take game_mutex<br/>game_send_response_to_uart() takes game_mutex INSIDE
                end
            end
            deactivate GQ
            
            GT->>BQ: xQueueReceive(button_event_queue, 0)
            activate BQ
            alt Button event in queue
                GT->>GT: game_process_promotion_button() / game_reset_game()
                Note over GT: Function runs in game_task - does NOT take game_mutex
            end
            deactivate BQ
            
            GT->>GT: game_update_timer_display() - Update time
            GT->>GT: Auto new game detection (starting position 2s)
            
            GT->>LT: led_set_pixel_safe() - DIRECT LED call (thread-safe, mutex INSIDE)
            Note over GT,LT: led_set_pixel_safe() internally takes led_unified_mutex<br/>Batch system: changes collected and committed in LED task
            
            GT->>GT: vTaskDelayUntil(100ms)
        end
    end

    rect rgb(240, 255, 255)
        Note over UT,URQ: UART TASK (Priority 3, 1ms cycle)<br/>MUTEX: uart_mutex - Protect UART output (prevent output overwrite)<br/>QUEUES: uart_output_queue (internal), uart_response_queue (responses from game_task)
        
        loop Every 1ms (uart_task main loop)
            UT->>WDT: esp_task_wdt_reset_safe()
            
            UT->>UT: uart_process_output_queue() - Process output queue
            loop For each message in uart_output_queue
                UT->>UM: xSemaphoreTake(uart_mutex)
                activate UM
                Note over UT,UM: Protect UART output - prevent overwrite
                UT->>UT: uart_write_bytes() / printf() - Write to UART
                UT->>UM: xSemaphoreGive(uart_mutex)
                deactivate UM
            end
            
            UT->>UT: uart_read_bytes() - Read from UART
            UT->>UT: uart_process_input_char()
            alt Complete command
                UT->>UT: uart_parse_command()
                alt Game command (MOVE, UP, DN, etc.)
                    UT->>GQ: xQueueSend(GAME_CMD_MAKE_MOVE / GAME_CMD_*)
                    Note over UT,GQ: Async communication - game_task processes in its cycle
                end
            end
            
            UT->>UT: vTaskDelay(1ms)
        end
    end

    rect rgb(255, 240, 255)
        Note over WT,GM: WEB SERVER TASK (Priority 3)<br/>COMMUNICATION: Direct call with game_mutex protection<br/>MUTEX: game_mutex - Protect when reading game state
        
        loop HTTP request handling
            WT->>WT: httpd_req_recv() - HTTP request
            alt POST /api/move
                WT->>WT: http_post_move_handler() - Parse JSON
                WT->>GQ: xQueueSend(GAME_CMD_MAKE_MOVE)
                Note over WT,GQ: Async communication - game_task processes in its cycle
                WT->>WT: HTTP 200 OK - {"success":true}
            else GET /api/status
                WT->>GT: game_get_status_json() - Direct call (thread-safe, mutex INSIDE)
                activate GT
                GT->>GM: xSemaphoreTake(game_mutex)
                activate GM
                Note over WT,GM: Direct call - fast synchronous communication<br/>game_get_status_json() takes game_mutex INSIDE function
                GT->>GT: Read game state (current_player, current_game_state, etc.)
                GT->>GM: xSemaphoreGive(game_mutex)
                deactivate GM
                GT-->>WT: JSON status
                deactivate GT
                WT->>WT: HTTP 200 OK - JSON response
            else GET /api/board
                WT->>GT: game_get_board_json() - Direct call (thread-safe, mutex INSIDE)
                activate GT
                GT->>GM: xSemaphoreTake(game_mutex)
                activate GM
                Note over WT,GM: Direct call - fast synchronous communication<br/>game_get_board_json() takes game_mutex INSIDE function
                GT->>GT: Read board[8][8]
                GT->>GM: xSemaphoreGive(game_mutex)
                deactivate GM
                GT-->>WT: JSON board[8][8]
                deactivate GT
                WT->>WT: HTTP 200 OK - JSON response
            end
        end
    end

    Note over GT,LT: Example: Physical move flow
    MT->>MM: xSemaphoreTake(matrix_mutex)
    activate MM
    MT->>GPIO: matrix_scan_all() - Detect piece lift (e2)
    MT->>MM: xSemaphoreGive(matrix_mutex)
    deactivate MM
    MT->>GQ: xQueueSend(GAME_CMD_PICKUP, e2)
    GT->>GQ: xQueueReceive()
    GT->>GT: game_process_pickup() - Save e2
    Note over GT: Function runs in game_task - does NOT take game_mutex
    
    MT->>MM: xSemaphoreTake(matrix_mutex)
    activate MM
    MT->>GPIO: matrix_scan_all() - Detect piece placed (e4)
    MT->>MM: xSemaphoreGive(matrix_mutex)
    deactivate MM
    MT->>GQ: xQueueSend(GAME_CMD_DROP, e4)
    GT->>GQ: xQueueReceive()
    GT->>GT: game_process_drop() - Detect e2→e4
    GT->>GT: game_is_valid_move() - Validate move
    alt Move valid
        GT->>GT: game_execute_move() - Execute move
        GT->>GT: game_check_end_game_conditions()
        GT->>LT: led_set_pixel_safe() - Move LED animation (thread-safe, mutex INSIDE)
        LT->>HW: led_strip_refresh() - WS2812B refresh
    else Move invalid
        GT->>GT: Error recovery (red LED)
    end

    Note over GT,UT: Example: UART move flow (with responses)
    UT->>UT: uart_parse_command("move e2 e4")
    UT->>GQ: xQueueSend(GAME_CMD_MAKE_MOVE, e2→e4)
    GT->>GQ: xQueueReceive()
    GT->>GT: game_process_chess_move()
    Note over GT: Function runs in game_task - does NOT take game_mutex
    GT->>GT: game_is_valid_move()
    alt Move valid
        GT->>GT: game_execute_move()
        GT->>GT: game_check_end_game_conditions()
        GT->>GT: game_send_response_to_uart() - Response (thread-safe, mutex INSIDE)
        Note over GT,URQ: game_send_response_to_uart() takes game_mutex INSIDE and sends to uart_response_queue
        GT->>URQ: xQueueSend(response_queue, success)
        GT->>LT: led_set_pixel_safe() - LED animation (thread-safe, mutex INSIDE)
        LT->>HW: led_strip_refresh()
    else Move invalid
        GT->>GT: game_send_response_to_uart() - Response (thread-safe, mutex INSIDE)
        GT->>URQ: xQueueSend(response_queue, error)
    end
    UT->>UM: xSemaphoreTake(uart_mutex)
    activate UM
    UT->>UT: uart_write_bytes() - Write response to UART
    UT->>UM: xSemaphoreGive(uart_mutex)
    deactivate UM

    Note over BT,GT: Example: Button event flow (promotion)
    BT->>GPIO: GPIO scan - Promotion button pressed
    BT->>BQ: xQueueSend(BUTTON_EVENT_PRESS, button_id)
    GT->>BQ: xQueueReceive()
    GT->>GT: game_process_promotion_button()
    GT->>GT: game_execute_promotion()
    Note over GT: Function runs in game_task - does NOT take game_mutex
    GT->>LT: led_set_pixel_safe() - LED feedback (thread-safe, mutex INSIDE)
    LT->>HW: led_strip_refresh()
