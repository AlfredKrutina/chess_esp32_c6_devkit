Detailed Description

Matrix Scanning Task - Detection of physical figures on a chest of drawers.

This file has two compile-time inputs selected by CONFIG_CHESS_MATRIX_INPUT:

  • GPIO reed matrix (default): row/column multiplex scan.
  • I2C Hall (CONFIG_CHESS_MATRIX_INPUT_I2C_HALL): reads raw ADC pairs from 4x STM32 slaves, runs the ported POC classification (energy + hysteresis + debounce) and collapses each pair to occupancy 0/1. Stable piece type and color are stable POC outputs; game_task uses them for move legality when this input mode is enabled.

WHAT DID THIS FILE DO?

This task scans the chest and detects the movement of pieces:

  1. Multiplexed 8x8 matrix scan (Language contacts under each field)
  2. Debouncing (ignores the "shaking" when lifting/placing the figure)
  3. UP/DN event detection (piece raised/placed)
  4. Send the move to game_task (when it detects a complete move)
  5. Error detection (bad sequence of events)

HOW DOES IT WORK?

MULTIPLEX SCANNING:

  • Activate row 0 (row select GPIO)
  • Honor 8 columns (column read GPIO)
  • Save state -> squares_state[0][0-7]
  • Deactivate row 0
  • Repeat for rows 1-7
  • Total time: ~10ms (full scan)

DEBOUNCING:

  • Each sensor must be stable for 3 scans in a row
  • Only then do we detect the change (UP/DN)
  • Ignores "shudder" during manipulation

PIECE TRACKING:

  • State: IDLE -> PIECE_UP -> PIECE_DN -> IDLE
  • UP on e2 -> we wait for DN somewhere else
  • DN on e4 -> move e2-e4 detected!
  • Send to game_command_queue

COMMUNICATION (FIFOS)

QUEUE - We send detected moves:

  • game_command_queue -> Send a move of type GAME_CMD_MOVE_DETECTED

NO MUTEX - Task is read-only (only read GPIO)

HARDWARE (GPIO MAPPING)

ROW SELECT (8 pin, active LOW):

  • GPIO 10-17: Select the box row

COLUMN READ (8 pin, pull-up):

  • GPIO 18-25: Reading language contacts (Reed switches)

Language contacts: I detect the magnet in the figurine

  • LOW = Figure present
  • HIGH = Empty field

CRITIC OF RULES

Warning
WHAT NOT TO DO:
  1. NEVER have debounce delay! Without debounce it will detect "shakes" as tens of events
  2. NEVER shorten the scan interval below 10ms! GPIO multiplex needs time to stabilize
  3. NEVER send a move directly to game_execute_move! ❌ game_execute_move(&move); // Access from another task! ✅ xQueueSend(game_command_queue, &cmd, ...); // Pass the queue
  4. ALWAYS check queue overflow! If game_task is busy, the queue may fill up

◆ squares_scan_row_internal()

static void squares_scan_row_internal ( uint8_t  row)
static

Scans one row of a matrix (mutexless internal functions)

This function scans one row of an 8x8 reed switch matrix. Before scanning sets all row pins to HIGH (inactive), then activates the current row set to LOW, wait 5 ms for signal stabilization, clean column pins and set the line back to HIGH.

Parameters
rowRow number (0-7)

Hardware logic:

  • Row pins are DRIVE (outputs) - you actively set the state
  • Column pins are SENSE (input with pull-up) - read them
  • Active row = LOW (pulls the column pin to LOW if there is a piece/reed switch closed)
  • Inactive row = HIGH (column pin remains HIGH if there is no figure)

Before activating the current row, all row pins are set to HIGH. This ensures that the other row pins do not interfere with reading column pin. Without this, the figures would be in one column on different boards could cause false detection (if row pin remains LOW, column pin would be LOW even when we scan other rows).

Stabilization wait: After activating the row pin to LOW, it waits 5 ms for correct establishing the voltage state. Without this waiting, something could go wrong reading the status of the column pin due to electromagnetic interference and capacitance effect.

Note
Callers must hold the squares_mutex before calling this function
