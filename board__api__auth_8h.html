Detailed Description

Board REST API token (NVS) + HTTP Bearer check for sensitive endpoints.

Auth matrix (HTTP)

  • Public GET (No Bearer): eg /api/status, /api/board, /api/game/snapshot, /api/wifi/status, /api/system/firmware, /api/system/ota/status (onboarding).
  • Admin POST (/api/system/ota, /api/system/factory_reset, paths under /api/wifi/, …): a valid Bearer is always sufficient. If WEB_LOCK is on and Bearer is missing or invalid → 403 web_locked. If WEB_LOCK is off (default), those admin POSTs from LAN still go through without a header.

Command token (separate from api_tok): issued when a device finishes pairing. POST /api/move and a command frame on /ws always require one of the three device tokens, even when WEB_LOCK is off. Snapshot reads stay open. While one commander holds the board, a different valid token gets board_busy.

Token: 32B random, in header as Authorization: Bearer <64 hex characters>.

BLE (see ble_task_conn_is_encrypted)

  • ota_start, ota_ble_begin, ota_ble_abort, ota_ble_status, wifi_sta_config, wifi_ap_set, factory_reset: require an active encrypted link (after SMP).

Device command tokens (max 3), stored beside the admin api_tok.

A phone learns its token from the BLE cmd_ack notify code=paired. A host without BLE learns it from POST /api/pair, and only while the pairing window is open. Both paths use the same 32-byte token style.
